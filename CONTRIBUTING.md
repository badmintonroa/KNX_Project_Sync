# Contributing

Thanks for helping! Bug reports and wrong detections are just as welcome as code. See [Contributing in the README](README.md#contributing) for what to put in an issue.

## Layout

```
custom_components/knx_project_sync/
  mapping/          port of the knx2home detection (plain Python, no Home Assistant)
  plan.py           diff between the project, the last import, the panel choices and your own YAML
  importer.py       parse, plan, apply (package file, reload, registry, areas), packages fix, removal
  writer.py         package file, unique IDs from YAML
  packages.py       find or add `homeassistant: packages:` in configuration.yaml
  yamledit.py       take entities out of your own YAML (with backup)
  config_flow.py    setup and options: only choose the source
  websocket.py      API of the panel and its registration
  repairs.py        one-click fix of the packages line
  frontend/         bundled panel (source in /frontend)
  sensor.py, diagnostics.py, services.yaml, strings.json, translations/
frontend/           panel (Lit, TypeScript)
schema/             JSON schema of the manifest between detection and import
docs/               design notes (German): feasibility study, manifest, port notes, import
tests/              pytest: port, plan, packages, Home Assistant integration; fixtures and golden files
tools/              fixture generator, knx2home reference generator
```

The detection produces a manifest ([docs/manifest-v1.md](docs/manifest-v1.md)). The import turns it into a plan, the panel edits the plan, and *Apply* writes it ([docs/import.md](docs/import.md)).

## Setup and checks

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements_test.txt
pytest
ruff check custom_components tests tools/fixtures
ruff format custom_components tests
```

Panel:

```bash
cd frontend
npm ci
npm run build        # writes custom_components/knx_project_sync/frontend/knx-project-sync-panel.js
npm run check        # TypeScript
npm test             # smoke test in Chromium (light, dark, phone width)
npm run screenshots  # docs/images/*.png for the README
```

Commit the built panel together with its source, the integration ships the bundle.

CI runs pytest and ruff, hassfest, the HACS validation, the panel build and smoke test, and the two comparisons with knx2home below.

## Detection and knx2home

The detection is a port of [knx2home](https://github.com/badmintonroa/knx2home) and has to give the same result. [docs/port-notes.md](docs/port-notes.md) lists the intended differences.

- `tests/test_mapping_parity.py` compares the port with golden files generated by knx2home.
- The CI job *real ETS projects* compares both on the test projects of xknxproject.

To regenerate fixtures and golden files (knx2home checked out next to this repository):

```bash
python tools/fixtures/build_fixtures.py
(cd ../knx2home && npm ci)
cd tools/reference && npm ci && npm run generate
```

The CI regenerates the golden files on every run and weekly with the current knx2home `main`. If knx2home changes its behaviour, the job fails and the port has to follow.

A fix for a wrong detection should go to knx2home as well, or be listed as an intended difference in the port notes.

## Translations

- Integration (setup, settings, repairs): `custom_components/knx_project_sync/strings.json` is the source, `translations/en.json` and `translations/de.json` are kept in line with it.
- Panel: `frontend/src/strings.ts`, one object per language.

## Releases

Versions follow [SemVer](https://semver.org). While the version starts with `0.`, anything can still change. `-beta.N` versions are GitHub pre-releases.

1. Raise the version in `custom_components/knx_project_sync/manifest.json`, `const.py` and `frontend/package.json`. A test checks that all three match.
2. Add a section `## <version>` to [CHANGELOG.md](CHANGELOG.md).
3. After the merge to `main` the *Release* workflow creates the tag `v<version>` and the release, with the changelog section as text.
